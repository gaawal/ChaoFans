# 南巷 · 夜炒

React + TypeScript + Three.js 的第一人称炒饭原型，支持桌面鼠标和手机竖屏触控。默认使用 WebGPU；不支持时 Three.js 回退 WebGL2。右上角显示实际后端。

## 启动

```sh
npm install
npm run dev
```

打开 http://127.0.0.1:5173/ 。开发服务器只监听本机；GLB、HDR 需要 HTTP 加载，不能双击 HTML 启动。

## 这一版

首页与第一人称视角使用同一辆三轮餐车。点击开始营业后，镜头走近车上的不锈钢工作台；锅、备料、瓶子、勺和手均来自本地 Blender 导出的 `playable-cart.glb`。

- 胡萝卜为细长丝，洋葱为弧形薄片，腊肉有瘦肉/脂肪/肉皮分层，葱花为中空切段，米饭为独立米粒；甜玉米粒、青豆、火腿丁各有独立造型。锅内、勺上与备料盘复用相同模型形状。
- 直接拖动双手，不提供下料、翻炒、颠锅等动作按钮。
- 右手来回炒过后松手会沿最后一次铲动方向短距离往复，不会自动绕圈；重新抓住右手立即接管。左手抓住锅柄晃动会摇锅，快速晃动触发颠锅。
- 转腕后按停留时间倒油/酱油/蚝油，食材画圈翻勺才投入；各食材独立计算受热时间。
- 灶台左前有煤气旋钮：按住手左右拖动调火力，火苗随之伸缩变色——文火偏蓝，猛火转黄红；火力直接决定锅温上限，关火后锅自然降温。
- 火焰分三层燃烧：蓝色燃气焰芯、黄色焰体、红色火舌，各自独立噪声闪动，随火力共同涨落。
- 火焰像素按锅的真实曲面遮挡，不会从锅底穿进食材；锅温超过约 185°C 时淋油会在锅内短暂爆火，伴随嘶响与噼啪声。锅温实时显示在右侧。
- 米饭和配菜以固定大小的独立粒子受重力、锅面、锅铲及彼此碰撞影响；颠锅后在世界空间抛起再落下，熟度只改变材质颜色。油、酱油和蚝油有各自粗细、颜色和下落液滴。
- 菜单是十道有名字的菜：黄金蛋炒饭、腊味炒饭、火腿炒饭、田园素炒饭、金玉满堂炒饭、腊味双拼炒饭、扬州炒饭、什锦炒饭、五彩腊味炒饭、全料豪华炒饭；配菜取自台面上九个料盘。
- 锅铲是全场唯一一把：谁的手拿起就跟着谁，放在台面前沿后，任意一只空手都能再拿起来；空手铲不起料。
- 锅架是贴着锅底曲率做的八条铸铁爪，锅坐在爪上而不是插进爪里；锅被拖动时只可能贴上、抬起或绕开备料盘和调料架，不会穿过去。
- 色香味随操作变化，空锅无法出餐，烧焦/缺料/未熟会减分；五单营业、收入经验、升级三选一。
- 菜价按荤素计：一荤 ¥4、一素 ¥2、底价 ¥4（素炒饭 ¥8 起，全料豪华炒饭 ¥16）。
- 暂停、页面隐藏自动暂停、可关闭的煎炒声音。松手后正在下落的锅属于物理，不属于计时：就算正好在这半秒里暂停或收单，它也会自己落稳，不会卡在半空。

## 鼠标操作

1. 按住画面里的手，拖到油瓶/酱油瓶/红盖蚝油瓶，松手后才握住。经过物体不会自动拿取。
2. 再抓这只手移到锅口，画一个小圆转腕。按住时持续倒，松手停止但仍持瓶；拖回原瓶位或桌前空白区松手归还。蚝油流速更慢、酱体更粗。
3. 持勺移到料盘，在盘上来回划动两三次，看到勺上装料；移到锅口画圈翻勺，食材受重力落入锅。
4. 右手拖进锅里，来回划动。松手后沿最后的铲动方向继续短距离往复；重新抓住这只手立即接管。铲头位置约束在锅和米饭表面，邻近饭粒随之被推开。
5. 手拖到木锅柄后松开握住；再次抓手向上拖可把锅提离灶台，快推快拉会颠锅。另一只手会跟随移动中的锅继续炒。
6. 松手时按位置决定锅去哪里：在灶口附近松手，锅顺着重力落回锅架；拖到台面前沿松手，锅落在台面上，手也彻底放开；在别处松手就仍然握着，锅不会瞬移。
7. 想放下锅铲时，把它拖到台面前沿松手。锅铲平放在台面上；想再拿，空手握到同一处松手即可。手里握着锅铲时去抓瓶子或锅柄，锅铲会先被搁在台面上，不会凭空消失。
8. 灶台左前的煤气旋钮：按住任意一只手移到旋钮上，左右拖动就是火力，松手定型。越向右火越大。
9. 炒好后，把持勺的手拖到工作台右边出餐碗并松开。
10. `Esc` 暂停/继续。

## 手机竖屏操作

- 单指触碰瓶子、锅柄或锅铲后直接拖动，松手放下瓶子或锅；瓶子会留在台面上的放置位置。按住锅铲在食材上划动可取料，在锅中划动可炒饭。
- 保持第一根手指按住物体，第二根手指绕它旋转：持瓶在锅口转腕倒液体，满勺在锅口翻转下料，握锅时改变倾角。
- 触碰空白处向左、右滑动，镜头沿餐车移动，查看竖屏中未显示的料盘和旋钮。

## 主要文件

- `assets/source/playable-cart.blend`：当前完整餐车、工作台、食材、工具、双手的 Blender 源文件。
- `public/models/playable-cart.glb`：游戏实际载入的统一模型。
- `public/models/playable-cart-layout.json`：世界坐标、抓取区域、摄像机和器具锚点。
- `scripts/build_playable_cart.py`：可重复执行的 Blender 建模与导出脚本。
- `src/scene/StreetScene.ts`：WebGPU 场景、镜头、抓取与锅气特效。
- `src/scene/FoodPhysics.ts`：固定时间步的食材重力与碰撞。
- `src/scene/LiquidStream.ts`：油、酱油、蚝油的液流和液滴。
- `src/scene/mobileInput.ts`：手机单指抓放、双指旋转与横滑视角。
- `src/audio/KitchenAudio.ts`：燃气、油锅、锅气和颠锅音效。
- `src/game/simulation.ts`：连续双手操作与烹饪评分。
- `src/game/kitchen.ts`：锅的实体模型——锅底曲率、铸铁锅架、台面高度、备料盘与调料架，以及放手后锅落到哪一层。
- `assets/source/hyper3d-cart-finished.blend`：Hyper3D 生成后标准化的原车来源。
- `assets/source/hyper3d-provenance-v2.json`：云端任务来源记录。
- `docs/hyper3d-tools.json`：实际查询到的 Hyper3D MCP 工具。

旧版 `street-station` / `hyper3d-cart.glb` 保留为历史素材，当前游戏不加载它们。`engine.ts` 和旧测试也只保留作历史实现。

## 检查与重建

```sh
npm test
npm run build
npm run models
```

`npm run models` 使用 `/Applications/Blender.app/Contents/MacOS/Blender` 重建完整餐车、导出 GLB、保存源文件并渲染 QA 图。其他系统替换 Blender 路径。此过程不调用云端，也不消耗 Hyper3D 积分。

## 当前边界

这是写实方向的可玩验证版。双手来自 Blender 骨骼模型，运行时驱动手指与腕部；食材使用适合浏览器的粒子碰撞解算，火焰和液体使用实时特效，并非离线流体模拟。城市远景是 HDR 全景，顾客目前以订单呈现，尚无写实顾客人物与步行动画。炒粉、局外经营和完整技能树仍待扩展。手机竖屏布局和手势逻辑已在浏览器及自动测试中检查，仍建议用实际手机检查多指手感和性能。

环境来自 Poly Haven 的 CC0 Shanghai Bund HDRI：https://polyhaven.com/a/shanghai_bund 。实际模型来源与生成流程见 `docs/ASSET_PIPELINE.md`。
