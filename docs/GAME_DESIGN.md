# 南巷 · 夜炒 — 当前可玩方向（2026-09-27）

以同一辆三轮餐车为整个厨房，菜单镜头移入工作台。玩家按住某只手获得鼠标控制权；手明确握住物品后，经过别的东西也不换物。

动作分为握持、取料、投放、连续翻炒、提锅五种。手拖到瓶/锅柄松开确认握持；持勺在料盘来回扫动铲料，锅口小圆翻勺倾倒；瓶子小圆转腕后按住连续倒；翻炒经过学习后松手持续；锅可以真正离开炉子，离炉逐渐降温。重新抓手即接管，松开另一手保留其工作状态。

放手必须落到实物上。锅的落点由它自己的位置决定：在灶口附近松手就沿重力落回锅架，在台面前沿松手就落在台面上并彻底松手，在别处松手则仍然握着——任何时候都不会瞬移回灶。锅是刚性回转体，只有锅底和锅沿能接触别的东西：铸铁爪按锅底曲率做成贴合的坐圈，锅横向滑动时沿爪面爬升，备料盘与调料架把它挡住或让它贴着面滑开，所以既不会插进锅架，也不会穿过盘子。锅铲和锅都只有一件：锅铲可以在台面前沿放下、由任意一只空手再拿起；手里有锅铲时去拿瓶子或锅柄，锅铲会先被搁到台面上。

内部计算独立食材受热、翻炒、油膜、调味时机、焦糊和客人耐心；外部只展示色香味和简短提示。食用油、酱油、蚝油为三个独立物品。蚝油与酱油互补，初期不强制两者都加。

已实现五单、10/12/14/16定价、质量结算、经验和升级三选一。火焰和米粒可夸张，但基础接触、握持和重力方向必须可信。顾客暂以订单呈现，写实人物/语音、完整手骨骼IK、炒粉与局外经营未完成。

# 最初的设计草案：先把一口锅做爽

## 体验目标

玩家每次动作都应立刻收到可读的反馈：锅往上飞、米粒聚成弧线、火苗蹿起、连击音变亮、客人眼睛发亮。色香味是成果反馈，火候和温度是后台参数，不把百分比计算交给玩家。

## 核心循环

接单 → 看荤素组合 → 按短流程下料 → 左右手交替连击 → 颠锅收尾 → 交单 → 色香味与满意度结算 → 经验升级 → 三选一 → 下一单。

第一版一局五单，顾客耐心 75 秒。成功流程可在 15–30 秒内完成；较宽的客人耐心给新手读步骤和恢复失误的机会。每个步骤的最佳动作间隔约 0.5–1 秒，操作窗口约 5–8 秒。后续可调整到每单 30–45 秒，并增加份量、连续颠锅、切换顾客和更丰富的动作，而不单纯拉长等待。

## 左右手是两个有限资源

| 手 | 默认工具 | 动作 | 选择压力 |
| --- | --- | --- | --- |
| 左 | 锅柄 | 稳锅、颠锅、猛火 | 颠锅有收益，但需要右手退出锅心 |
| 右 | 锅铲 / 料勺 | 下料、翻炒、调味、出锅 | 提前操作会降低收益，乱序会掉连击 |

第一版用明确的动作占用时长做冲突判定，不用难以解释的物理引擎碰撞。锅本身例外：它按解析高度场求支撑、按凸块推出求解横移（`src/game/kitchen.ts`），因此锅与锅架、备料盘、调料架之间的接触是真实几何。第二版加入工具插槽、动作预备态和可视化左右手落点，让玩家能主动选择换手、交叉或等一拍。只有错误进入共同工作区才打架；左手稳锅配右手翻炒应该持续加分。

## 后台判定与表面反馈

| 阶段 | 后台判定 | 玩家看到的反馈 | 主要增长 |
| --- | --- | --- | --- |
| 淋油打蛋 | 是否按顺序、节奏是否及时 | 滋啦、金色涟漪 | 色、香 |
| 荤素入锅 | 荤菜炒够次数、素菜不过度等待 | 肉色变化、葱青菜绿 | 味、色 |
| 米饭翻炒 | 连续动作与动作间距 | 饭粒散开、金色闪点 | 色 |
| 沿锅调味 | 时机和订单口味 | 酱汁蒸汽、精准命中 | 味 |
| 猛火颠锅 | 双手协同、颠锅高度、接锅成功 | 火焰爆、饭粒高抛、客人爱心 | 香、色 |
| 出锅 | 总质量与等待 | 评级、零钱、经验 | 收益 |

当前版本采用简化判定。下一版再加入“酱油太早”“肉未熟”“撒料偏离”的具体失败表现，仍以短词和视觉表达，不出现温度或蛋液比例面板。

## 升级设计

| 系 | 首个能力 | 后续分支方向 |
| --- | --- | --- |
| 锅功 | 一飞冲天：高度和香气增益 | 二段颠锅、空中接饭、龙卷出锅 |
| 勺功 | 无影快勺：速度和色条增益 | 推拉连段、环形翻炒、铲饭暴击 |
| 火功 | 烈焰掌门：猛火与抗焦糊 | 蓝火、火龙卷、救焦翻盘 |
| 油功 | 爆香开场：前期香条收益 | 热油扩散、少油高手、葱油暴击 |
| 蛋功 | 金包银：色条收益 | 双蛋、蛋花雨、蛋壳失误补偿 |
| 调味功 | 灵魂一撒：味条收益 | 精准撒盐、辣椒连击、酸豆角惊喜 |
| 耐力 | 永动大厨：双手恢复与判定宽容 | 忙中不乱、冲突恢复、长连击保底 |

目前升级只在单局内有效，每局可形成不同路线，最高营业额跨局保存。完整局外成长等玩法确认后再加，避免过早堆系统。

## 视觉与声音顺序

1. 先确认第一人称视角、锅的位置、双手辨识与左右手节奏。
2. 食材实例化、抛物线、蒸汽、火焰、反馈词和音效连成一个动作。
3. 双手和顾客更换成正式角色，补骨骼动画和表情。
4. 锁定 UI 规范后替换 React 覆盖层，不影响游戏状态机。
5. 增加夜市音景、点单语音、拖拽手势、客人口味和具体错料。
6. 用真实低端设备测试 WebGPU/WebGL2 与帧率，再扩充场景。

## 技术边界

React 管理 UI；Three.js 管理 3D 和动画；纯 TypeScript 状态机管理玩法。模型采用 GLB；Hyper3D 负责外观生成，Blender 负责尺度、朝向、材质、网格和交互对象。生成整车适合展示镜头，贴近手的台面和锅勺必须单独制作。火焰和米粒用实例化视觉效果起步，后续有性能需要时再迁移为 TSL/GPU 粒子。
